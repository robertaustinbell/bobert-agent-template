# Security policy

## Supported state

Security and privacy-boundary fixes are maintained on the current default branch. Tags and GitHub releases are immutable historical snapshots and do not receive backports unless a specific checkpoint explicitly states otherwise. Use an exact commit when reporting or reproducing a defect.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting for privacy-boundary bypasses, identity or authority inheritance, credential exposure, unsafe adoption behavior, validator bypasses, or other flaws whose public disclosure could expose a person or system. Open the repository's **Security** tab and choose **Report a vulnerability**. Share only the minimum detail needed to reproduce the issue; never submit live credentials, personal records, private communications, or unnecessary runtime state.

Ordinary operating thought disagreements, field-test results, and non-sensitive improvement proposals belong in public issues or pull requests. If a report cannot be made useful without exposing private information, do not publish that information; describe the general failure privately at the minimum safe granularity.
