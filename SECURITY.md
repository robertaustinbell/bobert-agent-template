# Security policy

## Supported versions

Security and privacy-boundary fixes are supported on the latest published release. Earlier snapshots may be useful provenance but do not receive fixes unless explicitly stated.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting for privacy-boundary bypasses, identity or authority inheritance, credential exposure, unsafe adoption behavior, validator bypasses, or other flaws whose public disclosure could expose a person or system. Open the repository's **Security** tab and choose **Report a vulnerability**. Share only the minimum detail needed to reproduce the issue; never submit live credentials, personal records, private communications, or unnecessary runtime state.

Ordinary doctrine disagreements, field-test results, and non-sensitive improvement proposals belong in public issues or pull requests. If a report cannot be made useful without exposing private information, do not publish that information; describe the general failure privately at the minimum safe granularity.
