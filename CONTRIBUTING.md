# Contributing

Propose changes against the owning layer. Identity changes belong in `SOUL.md`; cross-domain judgment in `doctrine/`; governance in `GOVERNANCE.md`; procedures should normally live outside this starter as runtime skills.

For evidence from applying an existing concept, start with [FIELD-TESTING.md](FIELD-TESTING.md) and use the concept field-test issue form. Identify the template tag or commit tested. Useful reports include null results, failures, excess ceremony, and cases where another explanation fits better—not only apparent successes.

For a proposed repository change, explain the decision effect, scope, strongest objection, known failure, and what evidence would reverse the change. Run both scripts before submitting.

Never include personal records, credentials, transcripts, proprietary material, machine paths, account identifiers, runtime state, or sensitive authorization details.
